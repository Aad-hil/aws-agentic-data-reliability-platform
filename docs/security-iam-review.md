# Security and IAM Review — Phase 6.3

## Scope

This review covers the deployed AWS execution boundary: Amazon S3, EventBridge, AWS Lambda, Amazon Bedrock, CloudWatch, and the IAM permissions generated by AWS SAM.

The objective is least privilege, secure data storage, controlled model access, and prevention of accidental public exposure. This is an architecture/configuration review, not a formal penetration test.

| S3 public access | All four S3 Public Access Block controls enabled | **PASS** |

## IAM assessment

The Lambda execution role follows a narrow service/action model:

- S3 read access is limited to the generated reliability bucket.
- S3 write access is limited to the generated reliability bucket.
- Bedrock access contains only the two model-inference APIs used by the adapter.
- CloudWatch access contains only `PutMetricData` and adds a namespace condition for `AgenticDataReliability`.
- EventBridge invokes Lambda through the SAM-generated event integration.

The main residual IAM finding is the Bedrock `Resource: "*"` scope. Unlike the S3 permissions, Bedrock model resources can vary by model and inference-profile type, including cross-region inference profiles. Hard-coding a model ARN here would reduce portability and could break deployment when the configured model changes.

For this portfolio implementation, the broad Bedrock resource is therefore an explicitly documented limitation rather than an unnoticed privilege. The action set is still constrained to inference operations; administrative Bedrock APIs are not granted.

### Future hardening

If the platform is moved toward a fixed production model, replace the wildcard Bedrock resource with the exact model/inference-profile ARN(s) supported by the deployment configuration. That change should be accompanied by an integration test against the selected region and model.

## Data protection assessment

The reliability bucket now has:

1. AES-256 server-side encryption.
2. S3 Bucket Key enabled.
3. Versioning enabled for recovery from accidental overwrite/deletion.
4. All four S3 Public Access Block settings enabled.
5. An explicit deny for requests where `aws:SecureTransport` is false.

No public bucket policy or public-read grant is part of the stack.

## Operational security

Lambda uses structured JSON application logs with INFO application logging and WARN system logging. The log group has an explicit retention period instead of indefinite retention. The log group is retained during stack deletion/replacement so operational evidence is not removed accidentally.

Automatic destructive remediation remains disabled. The multi-agent layer interprets deterministic evidence and generates advisory recommendations for human review.

## Verification

Static contract tests verify the security controls without requiring AWS credentials:

```bash
python -m pytest tests/test_deployment_contract.py -q
```

A live AWS security review should additionally verify the deployed IAM role policy, S3 Block Public Access state, bucket policy, CloudTrail activity, and AWS Config/Security Hub findings when those services are enabled in the target account.

## Portfolio conclusion

**Phase 6.3: PASS with one documented limitation.**

The AWS boundary has explicit encryption, public-access, transport, versioning, logging, and least-privilege controls. The only intentionally broad permission is Bedrock model inference resource scope, which is constrained by action and retained as a documented portability trade-off until the deployment standardizes on a fixed model ARN.
